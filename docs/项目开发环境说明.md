# 项目环境说明：Qwen-Image-2.1

## 1. 宿主操作系统与硬件

### Windows

- 操作系统：Windows 10 Pro
- 主要用途：宿主系统、GPU 驱动及开发环境承载。

### WSL2

- Linux 发行版：Ubuntu 24.04.5 LTS
- 内核：WSL2 Linux 内核
- 项目开发主要基于 Linux 工具链和文件系统。

项目文件应优先放在 WSL 的 Linux 文件系统中，以获得更好的 Linux 文件权限和大量小文件读写性能。不要默认使用 Windows 原生路径或 Windows Python 环境。

### GPU

- 显卡：NVIDIA GeForce RTX 5070 Ti
- 显存：约 16 GB
- 当前 PyTorch 基础镜像：`pytorch/pytorch:2.14.1-cuda13.0-cudnn9-devel`

GPU 验证应以实际 PyTorch 运行结果为准，不要仅凭宿主机的 CUDA 版本号判断兼容性。

## 3. Python 项目与依赖管理

项目使用 uv 管理 Python 环境和依赖，核心文件包括：

- `pyproject.toml`：项目元数据、依赖声明及开发工具配置。
- `uv.lock`：锁定依赖解析结果。
- `.python-version`：指定项目 Python 版本。

目标虚拟环境路径为：

`/workspace/.venv`

uv 相关配置：

- `UV_PROJECT_ENVIRONMENT=/workspace/.venv`
- `UV_CACHE_DIR=/home/ubuntu/.cache/uv`
- Python 目标版本为 `3.11.14`

正式项目依赖应通过 uv 管理：

```bash
uv add <package>
```

按锁文件同步依赖：

```bash
uv sync --frozen
```

运行项目代码：

```bash
uv run python <script.py>
```

具体命令应根据当前任务的工作目录和实际环境调整。

依赖管理原则：

1. 新增正式依赖时更新 `pyproject.toml` 和 `uv.lock`。
2. 不将临时安装的依赖视为正式项目依赖。
3. 不随意升级 PyTorch、CUDA 或 Python。
4. 更换 Python 版本或关键二进制依赖后，重新创建并同步虚拟环境。
5. 出现依赖安装错误时，先检查锁文件、环境变量、虚拟环境路径和文件权限。

## 4. GPU 与模型开发约束

当前 GPU 显存约为 16 GB。设计推理或训练实验时，应考虑显存容量，优先评估：

- 模型权重精度与量化方式。
- 模型加载和推理的显存峰值。
- CPU/GPU 内存卸载策略。
- 批量大小、分辨率和中间张量占用。
- Attention 实现、编译缓存及推理加速方案。

不要在未评估显存需求时直接启动高资源消耗任务。若发生 CUDA OOM，应分析显存占用和计算路径，而不是立即更换基础镜像或升级依赖。

验证 GPU 环境时使用：

```bash
python -c "
import torch
print('PyTorch:', torch.__version__)
print('CUDA available:', torch.cuda.is_available())
if torch.cuda.is_available():
    print('GPU:', torch.cuda.get_device_name(0))
    print('VRAM GiB:', round(
        torch.cuda.get_device_properties(0).total_memory / 1024**3, 2
    ))
"
```

## 5. 缓存与未来 Web 界面

项目区分以下缓存：

| 路径或标识 | 用途 |
|---|---|
| `/home/ubuntu/.cache/uv` | Python 依赖缓存 |
| `/home/ubuntu/.cache/huggingface` | 模型及相关资源缓存 |
| `/home/ubuntu/.cache/torch/inductor` | PyTorch 编译缓存 |

未来如果开发 Web 推理界面：

1. 先明确前端、后端与模型推理之间的接口。
2. 根据项目实际情况选择 npm 或 pnpm。
3. 通过锁文件保证前端依赖可复现。
4. 将 Web 构建与模型推理环境适当解耦，避免把前端依赖、模型权重和 Python 环境混在一起。
